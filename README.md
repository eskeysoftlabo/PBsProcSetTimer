# PB's Proc Set Timer 0.5.1

装備しているセットの効果について、**発動した瞬間・発動中・クールダウン**をリアルタイムに表示する ESO アドオンです(コンソール向け)。

**どのセットでも対象です。** ボーナス説明文に「N秒間」「N秒に1回」のような時間が書かれている**効果ごとに**、自動で行が出ます(時間のない能力値だけのセットは出ません)。1つのセットに効果が複数あれば、それぞれが独立した行とタイマーを持ちます。

## セットも効果も、アドオンの中に持たない

セットの一覧も、効果の数値も、アビリティIDも入っていません。ゲームから読み取ります。

| 必要なもの | どこから取るか |
|---|---|
| どのセットを何個装備しているか | 装備中アイテムの `GetItemLinkSetInfo`(アイテムのツールチップと同じ呼び出し) |
| 持続時間・クールダウン・発動までの遅延 | セットのボーナス説明文(`GetItemSetBonusInfo`)。「N秒間」「N秒に1回」などの言い回しを、全言語分の手がかり語で判別する(`Parse.lua`) |
| 発動の検出 | 戦闘イベントのアビリティ**名**(下の「照合のしかた」) |
| デバフの実際の残り時間 | `EVENT_EFFECT_CHANGED` の beginTime / endTime |

パッチで数値が変わっても、新しいセットが出ても、説明文が読めれば自動で追従します。

## 追跡するセットを選ぶ(設定画面)

設定画面の最初の区画「追跡するセット」で、どのセットを追跡するかを選べます。

- **一覧**: 時間のある効果を持つセットが並びます。いま装備しているセットが先頭で、その後に、これまでに装備したことのあるセットが名前順に続きます(装備していないものには「(いまは未装備)」が付きます)。チェックを入れたセットだけ、行が出ます。
- **新しく装備したセットも追跡する**: オン(初期値)なら、一覧でチェックを外したものを除いて、すべてのセットが追跡されます。オフにすると、**チェックを入れたセットだけ**が追跡され、初めて装備したセットはチェックを入れるまで追跡されません(「このセットだけ追う」はこの方法です)。
- **すべて入れる / すべて外す**: 一覧のセットすべてを一度に切り替えます。
- 画面を開くたびに一覧を作り直すので、装備を変えたあとに開いても最新です。一覧に出るのは40セットまでで、それを超える分は件数が出ます。
- チェックを外すと、タイマーが動いている最中でも、そのセットの行はすぐ消えます。
- チャットの `/procset hide` / `show` と同じ設定です(片方で変えればもう片方にも反映されます)。

行は、装備数でそのボーナスが有効になっている効果にだけ出ます。Perfected セットのボーナスは、ツールチップと同じく Perfected の装備数で数えます。行は最大8つです。

## 1つのセットに効果が複数あるとき

効果ごとに行とタイマー(発動中・クールダウン・対応づけたアビリティ)を別々に持ちます。

- **ボーナス行が複数ある場合**: ESOのセットボーナスは足し合わさって有効になるので、時間のある行が有効になっていれば、すべて別々の行になります(例: 3個効果と5個効果の両方に時間があれば、5個装備で2行)。
- **1つのボーナス行に効果が複数ある場合**: 説明文を文ごとに読み、次の2つの目印で効果を区切ります。区切った結果、時間のある効果が2つ未満なら、行全体を1つの効果として読みます(従来どおり)。
  - 「N秒に1回」のようなクールダウンの文は、直前の効果を閉じます。その次の文からは別の効果です。
  - 「N秒間」のような持続時間のある文が、すでに持続時間のある効果の続きに現れたら、別の効果です。例: 哀れなる活力(Wretched Vitality)の5個効果は、「…260…を15秒間」と「…130…を15秒間」の2文なので、2つの効果(クールダウンの文はありません)。
  - 時間の言い回しが読み取れなかった文は、区切りの目印にしません(クールダウンの言い回しを読み損ねて、1つの効果を2つに割る事故を避けるため)。
- **行の名前**: 効果が1つのセットはセット名だけです。複数あるセットは、その行が必要とする装備数を付けて `セット名 (3)`、`セット名 (5)` のようにし、1つの行の中に複数あれば `セット名 (5-1)`、`セット名 (5-2)` のように番号を付けます。名前が長いと、セット名の幅(設定の「セット名」の幅、初期値270)で省略されるので、必要なら広げてください。

### バーを切り替えたとき

- 効果やクールダウンが**動いている間は、行を消しません。** 切り替えでセットのボーナスが切れても(別のバーの武器が数に入らなくなるなど)、すでに敵に付いている効果と残りのクールダウンは続くので、その分を最後まで表示します。終わった時点で、ボーナスが切れたままなら行が消えます。
- 切り替えの直後に数え直しで一瞬だけ数が落ちることがあっても、**2秒以内に戻れば行は消えません。**
- 切り替えて戻したときは、タイマーを**リセットせず**に続きから数えます。
- 5個効果が切れて3個効果だけが残る場合など、効果ごとの行は互いに独立しています。切れた方の行は、タイマーが動いている間だけ残ります。
- セットの追跡をやめる(設定画面でチェックを外す、`/procset hide`)と、タイマーが動いていてもすぐ消えます。

## 照合のしかた(どのイベントがどの効果か)

1. **セット名との関係で一致**: アビリティ名がセット名と同じ、セット名の一部、またはセット名を含む(例: 「Martial Knowledge」⊂「Way of Martial Knowledge」)。有効な効果が複数あるセットでは、さらに1つに絞ります。次の順に候補を減らします(候補がなくなる手順は飛ばします)。
   1. その効果の説明文にアビリティ名が出てくる(かつ長さが合う)。
   2. **アビリティ自身の説明文**(`GetAbilityDescription`)に、効果の説明文と同じ数値が出てくる(例: どちらも「260」)。
   3. 効果の長さが持続時間と合う。
   4. 効果の説明文にアビリティ名が出てくる。
   5. イベントの種類(バフ/デバフは持続のある効果へ、ヒットは持続のない瞬間の効果へ)。

   それでも決まらなければ、**そのアビリティがすでに動かしている効果**、次に**まだどのアビリティにも動かされていない効果**、最後に先頭の効果です。つまり、同じセットの2つの効果は、別々のアビリティなら別々の行になります。ただし最後の「先着」の段階では、2つの行の対応が入れ替わることがあります。`/procset status` で、どのアビリティがどの行を動かしているか(とゲームが書いているその説明)を見て、違っていれば `bind` で直せます。
2. **説明文に書かれた名前で一致**(効果=バフ/デバフのみ): アビリティ名が効果の説明文にそのまま出てきて、**かつ効果の長さが説明文の秒数と合う**(±0.6秒)。「Major Brutality」のように多くのセットの説明文に出てくる標準バフを、自分のスキルで付いたときに取り違えないための条件です。

外れたときのための手動の逃げ道があります(下のコマンド)。

## 表示

- 初期の色: 緑: 発動中(残り秒数) ／ オレンジ: クールダウン(残り秒数) ／ 水色: 発動可能 ／ 灰色: 効果なし
- 発動した瞬間にバーが白く光ります。
- 色は設定画面で変えられます(下の「色」)。
- 効果が付いたあとも続くクールダウンは、同じ行に `発動中 3.2  CD 4.8` のように並びます。

## 位置とサイズ(設定パネルで変更)

- **表示全体**: 位置(左上の角を画面中央から)、大きさ(%)、行の高さ。
- **セット名 / バー / 状態テキスト**の3要素それぞれに、表示する・しない、横位置・縦位置(行の左端と縦中央から)、幅。バーは高さ、文字は大きさ(18〜42)も。
- 「表示のプレビュー」をオンにすると、サンプルの5行(発動中+CD、CD、発動可能、効果なし、発動の瞬間)が出るので、見ながら調整できます。

## 色(設定パネルで変更)

設定画面の「色」の区画で、状態ごとの色を指定できます。

- **対象の状態**: 発動中 / クールダウン / 発動可能 / 効果なし / 発動の瞬間(発動した瞬間に一瞬変わる色)。
- **指定のしかた**: 状態ごとに、赤・緑・青のスライダー(0〜255、5刻み)です。色を決めるダイアログは使いません。
- **バーと文字は同じ色です。** 状態ごとの色が、バーと、その横の状態テキストの両方に使われます。「効果なし」の行にはバーがないので、文字だけの色です。
- **確かめかた**: 「表示のプレビュー」をオンにして、設定画面を閉じると、5行のサンプルが各状態の色で出ます。
- **「色を初期値に戻す」**: 色だけを初期値に戻します。「設定をすべて初期値に戻す」でも戻ります。
- 初期値は、これまでの色とほぼ同じです(スライダーの5刻みに合わせて、わずかに丸めました)。

## コマンド `/procset`

| コマンド | 内容 |
|---|---|
| `on` / `off` | 表示のオン・オフ |
| `sets` | 装備中のセットと、それぞれに行があるか(ないならその理由) |
| `hide <ID または名前の一部>` / `show ...` | セットの追跡をやめる・再開する(設定画面のチェックと同じ。IDはまだ装備したことがなくても指定可) |
| `status` | 各行の装備数、説明文から読み取った時間、対応づけたアビリティ(とゲームが書いているそのアビリティの説明) |
| `log` | 最近の変化(バー切り替え、装備数、ボーナスの有効・無効)。装備数は、装備品から読んだ値とゲームがセットごとに持つ値を並べて出す |
| `text [セットID]` | 装備中のセット(またはIDで指定した1つ)のボーナス説明文の原文と、読み取り結果 |
| `probe` | セット装備中に出た自分のアビリティを一覧表示(対応づけに失敗した効果を探す。アビリティの説明も出す) |
| `bind <アビリティID> <セットIDまたは名前>[:<装備数>[-<n>]]` | アビリティを手動で結びつける。`:5` でその装備数で有効になるボーナスの効果、`:5-2` でその2番目の効果。`bind clear` で解除 |
| `ignore <アビリティID>` | 取り違えたアビリティを照合の対象から外す。`ignore clear` で解除 |
| `preview` | 位置決め用のサンプル表示 |

設定パネルは LibHarvensAddonSettings(任意)です。追跡するセットの選択のほか、戦闘中のみ、発動を検出したセットだけ表示、クールダウン明けの音、位置と大きさなどを設定できます。

- 同じセットの2つの効果が、同じ名前・同じ長さのアビリティで動くとき、アビリティの説明文の数値(260/130)と、先着順で割り当てるようにしました。

## 0.3.0 での変更

- 1つのセットに複数の効果があるとき、効果ごとに独立した行とタイマーで管理するようにしました(上の「1つのセットに効果が複数あるとき」)。
- これまで、時間のあるボーナス行が複数あるセットでは一番上の行だけを追っていました。いまは有効なすべての行を追います。
- `bind` で、セット全体だけでなく、その中の1つの効果を指定できます。保存済みの `bind` はそのまま使えます。

## 0.2.1 での変更

- バーを切り替えると、効果が動いていても行が消えてしまう問題を直しました(上の「バーを切り替えたとき」)。
- `/procset log` を追加しました。

## 0.1.0 からの変更(0.2.0)

- 3セット固定をやめ、装備中の全セットを対象にしました。
- 設定の保存形式を変えたため、0.1.0 の設定(位置など)は初期値に戻ります。

## まだ実機で確かめていないこと

オフラインのモック(`test/`、915項目)で、ロジック・表示・設定パネルを確認しています。PS5 では次が未測定です。

1. **日本語の説明文の言い回し。** 英語版は UESP の文言で確認済みですが、日本語版は読めていません。`/procset text` で読み取り結果を見るのが確実です(`status` の `placed by position` は、手がかり語に当たらず位置で判断した印)。
2. **アビリティ名の対応。** 実際のゲームがどんな名前を付けているかは未測定です。外れていれば `/procset status` の `matched` が空になるので、`/procset probe` で実際の名前を見て、`bind` で結びつけます。全セット対象になったぶん、説明文に標準バフの名前が出るセットでは、まれに自分のスキルのバフを効果と取り違えることがあります。その場合は `ignore` で外せます。
3. **バーを切り替えたときのゲームの数え方。** 切り替えの瞬間に装備数がどう動くか(一瞬落ちるのか、別のバーの武器を数から外すのか)は未測定です。2秒の猶予はその保険です。切り替えてから `/procset log` を実行すると、実際の動きが分かります。
4. **色のスライダー。** 状態ごとに3本、合わせて15本のスライダーが並びます。スライダーの操作感は、ほかのスライダーと同じ作りですが、15本を続けて動かしたときの画面の挙動は未確認です。
5. **設定画面の一覧の作り直し。** 一覧は、画面が選ばれた時と、画面の場面が表示された時に作り直します。これは PBsKillLog と同じ方式で(そちらは PS5 で確認済み)、このアドオンでは未確認です。装備を変えたあとに画面を開いても一覧が古いままなら、お知らせください。
6. **効果の切り分け。** 1つのボーナス行を複数の効果に区切る規則と、アビリティから効果を選ぶ規則は、実際のゲームでは確かめていません。とくに、(a) 日本語の説明文でも区切れているか(`/procset text <セットID>` の `effect n of m` の行で分かります)、(b) 2つの効果のアビリティが実際にどんな名前で、説明文に数値を含むか(`/procset status` と `/procset probe` で分かります)、の2点です。取り違えは `bind` で直せます。
7. **敵のデバフを追える範囲。** `EVENT_EFFECT_CHANGED` が、レティクルやボス以外の敵のデバフについても届くかは未確認です(届かなければ、現在のターゲットの分だけ表示されます)。
